# DESIGN.md

Committed visual world for Deepread (v2). Token source of truth: `packages/design-system/src/tokens.css` (+ TS mirror `tokens.ts`, theme catalog `themes.ts`). Surface mode: **Operate** (product UI; earned familiarity, restrained color, consistency over surprise).

**Direction: Structured Quiet, Linear skeleton.** A warm neutral paper ground, one user-selectable accent (default ink teal), glass on chrome and floating panels, hairline depth elsewhere. Content is the composition. v2.1 corrected an over-reaction: the cold white + bright blue + fully opaque chrome of the first W2 pass read as an unfinished admin template, and it overrode the user's long-standing preference for glass / capsule navigation. The 2026 "anti-glass" trend is evidence, not authority; the brief wins.

Product truth that did not change: foliate-js is the only rendering kernel, book typography is never re-flowed, reading performance outranks everything, local-first/private, all AI output reviewable.

## Tokens

Five scales. A bare value in a component file is a bug, not a preference.

- **Color** — `--ink-hue`(80, warm neutral) drives the ground; the accent has its own three axes `--accent-h/c/l`. Five presets in `accents.ts` (ink teal / terracotta / forest / ink blue / plum) change **only hue + chroma**; each world supplies its own lightness, so every preset stays readable in paper, graphite and OLED. A custom sRGB hex overrides `--color-accent` itself from JS, with `--color-on-accent` picked by WCAG relative luminance. Accent is a signal only: selected row, primary action, progress, reading state. Never add a second accent.
- **Type** — 8 steps: `--font-size-2xs`(11) `xs`(12) `sm`(13) `md`(15) `lg`(17) `xl`(20) `2xl`(24) `3xl`(30), each with a matching `--leading-*`. One system sans family for all UI; no display face in labels or buttons.
- **Space** — `--space-N` where **N is the pixel value** (2 … 64). 4px base, 2px half-steps.
- **Radius** — one shape per rank: `xs`(3) `sm`(6) `md`(8 control) `lg`(10 group) `xl`(14 card) `2xl`(16 bar) `4xl`(18 sheet). Semantic aliases `--radius-control/group/card/bar/sheet`. `--radius-full` is the capsule used by nav, toolbar controls and primary CTAs; the 87 legacy call sites are intentional, not drift. **Book covers use 2px + a 1px hairline** because a book is an object, not a surface.
- **Elevation** — `--z-*` eight ranks. Only values that outrank a _different_ module belong here.
- **Motion** — two layers: feedback (`--spring-snappy`, 150–200ms) and structure (`--spring-gentle`, 220–250ms). The old third "state" layer and the 350/560ms springs are gone; Operate mode does not wait for choreography.
- **Icon** — Phosphor, exactly three sizes: **14** inline/chip, **16** standard, **20** prominent.

## Themes

Three app worlds, not twelve near-duplicates: `pure-white` (warm paper, the `:root` default), `dark` (warm graphite), `oled` (pure black). `themes.ts` owns the ids, `tokens.css` owns the values, `tokens.test.ts` asserts the two agree. `LEGACY_APP_THEME_MAP` maps the twelve v1 ids at read time, so a saved preference never lands on a selector that no longer exists.

Reader **paper** themes are a separate axis and keep all nine options: paper is a reading asset, not chrome. Grouping them into light / warm / dark belongs to W3. Dark worlds set `--color-on-accent` to ink — white on a lifted accent is 2.4:1.

## Stylesheets

`apps/desktop/src/styles/global.css` is a **layer manifest + import list**, not a style file. The rules live in `styles/sections/` (12 files).

- **All 12 sections live in ONE `legacy` layer.** Giving each section its own layer was tried in W1 and was a mistake: layer order outranks selector specificity, so a later-layer `.sliding-indicator` beat an earlier-layer `.lib-sidebar-nav .sliding-indicator`, and 227 cross-layer specificity flips silently broke disabled / hover / selected states (the sidebar selection turned into a solid blue pill). Within one layer, specificity and source order work exactly as this CSS was written. A computed-style snapshot over 168 properties missed it because it sampled no state selectors; the cross-layer audit in `/tmp/deepread-layer-audit.mjs` is the check that catches it. Never split legacy sections into separate layers again. New code that must explicitly outrank legacy can open a new layer declared after `legacy`.
- **`tokens.css` stays unlayered.** Custom properties cascade too; an unlayered `:root` value must beat a layered one. This also fixed a real bug: `01-base.css`'s `:root{color-scheme:light}` used to beat `[data-app-theme='dark']` by source order, so dark themes shipped light native controls and scrollbars.
- **Append where you live.** New rules go in the matching section; a new domain gets a file and an `@import … layer(legacy)` in the position it must win from. `12-a11y-stats.css` stays last so its `prefers-reduced-motion` override still wins.
- **Verification** is a headless-Chromium computed-style snapshot (168 properties × 2 themes, `.workbuddy/baseline/*.json`) plus build/lint/format/typecheck/tests and bundle size. Byte-identical CSS was the right gate for a pure file split; a layer or palette migration necessarily changes bytes.
- **Same selector in two sections is allowed for exactly three reasons**: thicker pour, z-index raise, state recolour. The four multi-section selectors (`.modal-panel`, `.lib-sidebar`, `.library`, `.note-card`) were re-checked during W1: glass recipe / 860px responsive overrides / `content-visibility` patches with disjoint properties — not conflicts, left alone.

## Surfaces and depth

Three rungs, derived from the theme, never hand-picked:

| rung | token            | what lives there                             |
| ---- | ---------------- | -------------------------------------------- |
| page | `--surface-page` | the desk; never a component                  |
| card | `--surface-card` | anything you can point at                    |
| sunk | `--surface-sunk` | a hole **inside** a card: track, input, rail |

**Page ≠ card is the whole hierarchy.** A small OKLCH lightness gap is what makes a flat card legible; flatten it and every card fakes depth with a shadow.

- **Card = flat.** Radius `--radius-card`, background `--surface-card`, no shadow. A card that needs a shadow is secretly a floating panel.
- **Chrome bars wear glass** (`--glass-bg` + `--glass-edge` + `backdrop-filter`), as do menus, sheets and drawers. Page and card bodies stay opaque. `--reader .reader-top/.reader-bottom` swap the glass tint to the paper tone so a night book never floats under a cold white bar.
- **Glass is overlay-only**: command bar, menus, sheets, drawers. Its three ingredients must all stay (low tint, `blur(18px) saturate(1.9)`, stacked edge), or it reads as frosted plastic. Panels holding prose take the page tone (`--glass-bg-bar`).
- **Physical objects keep one shadow.** Book covers: 2px radius, 1px hairline, one soft rest shadow, one lift on hover. Never a three-layer stack.
- **Inside the reader the rungs are re-derived** from paper + ink (94/6, 88/12), so a night-paper book in a light app theme can never produce white text on a white card.
- Grouped lists: label _outside_ the card, rows _inside_, hairline between rows.

## First viewport and command bar

The library opens with a **quiet card**: a real page-to-card lightness step plus one hairline, a 120×164 cover, a `2xl` book title clamped to two lines at `max-width: 26em`, one line of `tabular-nums` progress as a sentence, and a single capsule CTA. The first W2 pass used a transparent row with a `3xl` title; on real data a 40-character Chinese title became a two-line text wall. Always verify with long real titles, never with a short injected sample. No decorative progress rail, no duplicate eyebrow, no equal-weight pills. The reading grid follows below and **does not repeat the featured book**: the card is that book's pinned place in the shelf, not a second copy. Progress copy follows the data — above zero it reads `读到 N%` with a `继续阅读` CTA; a just-opened book at `0%` reads `最近打开 · 尚未开始` with `开始阅读`. Never claim a previous session that did not happen.

`⌘K` opens `CommandBar`: one input answers both "which book" and "what do you want to do" (views, import, settings, sync, theme, matching books). It is a native `<dialog open aria-modal>` with `useModalFocus`, ↑↓/Enter/Esc, and ordinary readable buttons instead of a hand-rolled combobox. The shelf search field still exists for direct clicking; the two share one mental model.

## Responsive, motion, and paper

- **Grid density answers its own container, not the viewport.** `.shelf-viewport` carries `container-type: inline-size`; `@container (max-width: 720px)` drops a fixed column count back to `auto-fill`. Split view and parallel reading narrow the shelf while the window stays wide, which a viewport media query cannot see. The `760px` viewport rule stays as a fallback for engines without `@container`.
- **View Transitions keep chrome still.** `withViewTransition` is the single funnel for shelf / notes / stats; `.lib-sidebar` has its own `view-transition-name` so the rail does not fade with the content. `prefers-reduced-motion` short-circuits at the JS entry (the browser-run VT animation ignores the global CSS override) and the `::view-transition-*` pseudo-elements are neutralised as a second guard.
- **Reader paper grouping is display-only.** `READER_THEME_GROUPS` maps nine papers into light / warm / night rows. Positions in `READER_THEMES` are persisted as `themeIndex`; reordering them would silently change a returning reader's paper. Buttons still emit the original index, and a test asserts the groups cover every index exactly once.

## Accent system and book metadata

- **One accent, six presets, one custom slot.** Picker lives in Settings → 外观; the choice is stored as `deepread.accent` (`preset-id` or `custom:#rrggbb`). Presets set `data-accent`; custom clears it and writes inline `--color-accent` + `--color-on-accent`. `tokens.test.ts` asserts every catalogued preset has a CSS block with matching hue / chroma, and `accents.test.ts` covers parsing, round-trip and the contrast crossover.
- **The default accent is the desktop logo's blue.** The icon is a `#486ce3 → #5861d8` gradient with a `#5268de` average (OKLCH `L .564 / C .181 / H 271.5`). The `brand` preset takes that hue with chroma pulled back to `0.14` — the logo's raw `0.18` would turn white button text into a contrast failure and reintroduce the saturated blue this design already rejected. Lightness still comes from the theme block (`0.48` paper / `0.72` graphite / `0.76` OLED), which is why dark mode lands close to the icon while paper reads as a deeper indigo. Measured contrast on `--color-on-accent`: **6.56 / 7.12 / 9.06**. `:root` repeats the default hue / chroma so the first frame before React writes `data-accent` does not flash the old teal; a test pins the two together.
- **The accent row reserves room for its own selection ring.** The active swatch uses a `box-shadow` that extends 4px in every direction; the first swatch used to sit exactly on `.settings-body`'s left edge, whose `overflow-x: auto` clipped those 4px. `padding-inline: 5px` on `.accent-row` keeps the whole ring inside the drawable area, and six 28px swatches plus the custom picker still fit on one 410px row.
- **Book metadata is a line, not a badge.** Each tile shows `FORMAT · SIZE` under the author in tertiary ink with tabular numerals; the list view appends it to the subline. Missing files (`format === 'unknown'`) show the recovery sentence instead of inventing a format. Never stick a badge back on the cover.
- **The daily goal belongs to the bottom block.** Goal card and `.lib-sidebar-foot` share `.lib-sidebar-bottom` (`margin-top: auto`), so the card sits 8px above the footer hairline instead of floating in the middle. Narrow windows use `display: contents` so both children rejoin the horizontal sidebar.

- **Shelf density is spacing, not deformation.** Three presets (`comfortable` / `standard` / `compact`) write `data-density` on `:root` and change only `--shelf-min-col`, the grid gap and the list row gap. Cover aspect ratio stays 3/4 and all three metadata lines stay intact — a book is an object, so density means _how many per row_, never squashing the object. `standard` lives in the rules' fallbacks and needs no block of its own.

## Accessibility baseline (W4)

- **Keyboard entry**: the first focusable element in `.library` is `.skip-link`, targeting `#main-content` (`tabindex="-1"`). It hides with `transform`, never `display: none` — the latter drops it from the tab order. The target suppresses its own focus ring.
- **Contrast gate**: primary / secondary / tertiary ink on **card and page**, plus `--color-on-accent` on `--color-accent`, are measured in a real browser (OKLCH → linear sRGB → WCAG ratio). All pairs clear **4.5:1** in paper / graphite / OLED. W4.6 re-calibrated the paper world's ink ladder against the **page** ground as well as the card: the old tertiary read 4.70:1 on a card but only 4.16:1 on paper, which is exactly where `FORMAT · SIZE` and toolbar hints sit. It now reads 5.55 (card) / 4.84 (page), with secondary 7.64, primary 16.14 and on-accent 6.56; graphite / OLED are untouched (4.74 / 5.09 on card). `prefers-contrast: more` derives tertiary from the current world's secondary + primary, so one rule serves all three themes.
- **Token overrides live in `tokens.css` (unlayered)**. A `:root` inside the `legacy` layer can never beat it — layer order outranks specificity, the same trap that produced 227 cascade flips in W1. Only component rules for `forced-colors` belong in the a11y shard.
- **Forced colours** swaps accent / border / on-accent to `Highlight` / `CanvasText` / `HighlightText`, gives the selected indicator a system-colour border (its neutral grey fill disappears), and sets `forced-color-adjust: none` on book covers so artwork is not recoloured.
- **Charts have data twins.** The 7-day bars and the year heatmap are pure visuals with `title` only; each gets a `.visually-hidden` table — one row per day, twelve monthly rows for the year (never 365 rows). The tables stay in the accessibility tree without changing layout: screenshots with and without them are byte-identical. Assertions scoped to the whole page must exclude `table.visually-hidden` when checking a unique text node.
- **Motion has two independent paths, not one merged signal.** The system preference stays in its native `@media (prefers-reduced-motion: reduce)` blocks across the shards; a user who explicitly picks 减少动效 gets `data-motion="reduce"` on `<html>` and a parallel set of rules in `12-a11y-stats.css` plus duration tokens in `tokens.css`. Deliberately _not_ folded into one JS-resolved attribute: that would need a `matchMedia` listener and would leave an animation gap before React writes the attribute. `system` removes the attribute instead of writing a value — there is no `system` CSS block. `withViewTransition` short-circuits on either path (dataset first), so no snapshot is taken. The low-frequency picker sits last in Settings → 外观 so the commonly used shelf preferences stay in the first viewport.
- **Reduced transparency drops glass, not hierarchy.** `prefers-reduced-transparency: reduce` swaps `--glass-bg` / `--glass-bg-bar` / `--color-surface-glass` for opaque `--color-surface`, sets both blur tokens to `none`, and keeps a drawn hairline edge. Hardcoded `backdrop-filter` values are cleared by a wildcard component rule (a selector allowlist would silently miss the next glass panel); the modal scrim goes from 0.32 to 0.62 alpha. These token overrides sit **after** the app-theme blocks in `tokens.css`: `--color-surface-glass` is declared twice at equal specificity, so source order decides.
- **Hidden file inputs are not focus stops.** The three `.visually-hidden` `<input type="file">` (shelf import, backup restore, reader font import) are fired by a visible button's `.click()`; they carry `tabIndex={-1}` + `aria-hidden="true"`. The focus ring alone is not enough: `useModalFocus` / `useDrawerFocus` share one `focusableIn()` filter that drops `tabIndex < 0` and anything inside an `aria-hidden` subtree. Before this, Tab landed on an invisible, unnamed input. A 24-step real-browser Tab walk asserts zero such stops.
- **Dialog chrome is not a document landmark.** `<header>` / `<footer>` inside a `<dialog>` map to nameless `banner` / `contentinfo` landmarks, adding two empty entries to the screen-reader landmark list; both settings and book-info use plain `<div>` with the same classes. Icon-only close buttons carry `aria-label` in addition to `title`. Settings tabs own `id` + `aria-controls`, and `#settings-panel` is a `role="tabpanel"` labelled by the active tab — the AX tree reports `tabpanel 外观`.
- **Tablists are keyboard-complete.** One `handleTablistKeys` serves both the settings (4) and reader-prefs (2) tablists: ←/→ wrap, Home/End jump, focus follows the selection, and roving `tabIndex` leaves only the selected tab in the Tab order. It must `stopPropagation()`: the reader maps ←/→ to page turns on a `window` **bubble** listener, so without it one keypress would switch a tab and turn a page. `SlidingIndicator` only forwards `onKeyDown` for an explicit `role="tablist"` branch — a generic div with a handler is an unsemantic node (and an a11y-lint error). Other indicator uses (sidebar `nav`, smart filters, segmented controls) keep their original roles.

## Interaction invariants (carried over from v1)

These are engineering truths, not style preferences. They survived the redesign.

- **Group toolbars by intent, not widget type**; 2px inside a group, 8px between groups, an 18px hairline (a full-height rule in a 44px pill reads as a wall). Frequency decides what stays visible; the rest live behind `⋯` with shortcut hints.
- **One entry per question**: two buttons that both mean "settings" are a lookup cost with no payoff.
- **One row, one height**: set it on `height` (`--shelf-control: 36px`), never through padding. Declare the token where every caller can read it — a wrapper-scoped variable silently vanishes for the next caller.
- **Selection has two kinds**: navigation = _where am I_ (neutral sliding row fill, ink text, medium weight — **no accent bar**: once accents became user-selectable that stripe turned into a second signal and chopped up the sidebar edge); a switch = _which value is on_ (solid accent + `--color-on-accent`). Never accent-soft + accent text. Decoration never competes with the selection signal. **Only one group per page draws the navigation signal**: smart filters carry `.is-filter`, which hides their sliding indicator and leaves ink + weight + accent count. Two grey rows at once read as two different locations.
- **Collapsing is not hiding.** The sidebar narrows to a 64px icon rail — destinations, the selected row and the footer actions stay. `opacity: 0` would delete the "where am I" signal along with the width. Every icon-only control must carry its own `aria-label` + `title`: `display: none` on the label text removes it from the accessibility tree. Rail rules live under `@media (min-width: 861px)` so the narrow horizontal layout keeps its own rules.
- **A switch fills its row equally** (`flex: 1 1 0`), not by its label width; nest the radii inside the track; uneven labels want a grid, not a wrapped row.
- **A panel that scrolls scrolls one region** (`overflow: hidden` shell, `min-height: 0` pane). Scrolled content must be cut against a drawn edge with a fade no longer than the padding it covers.
- **Empty states teach and are sized by the area they reserve**; copy must match what the input actually does. Loading uses skeletons. **Zero is not a minimum** and **no data is not a chart**: draw the sentence instead.
- **A filled button is not disabled by opacity** (45% of accent still looks pressable and drops under 3:1); swap to a neutral fill + tertiary ink.
- **One class, one intent.** Two meanings need two names or a scope, never a second definition of the same selector.
- Every control ships hover / focus-visible / active / disabled / loading / error. Reduced motion is one global override in the last section (plus the parallel user-forced path described above); press is `scale(0.97)`; centred elements move with `translate`/`scale`, never `transform`.
- Menus use `ActionMenu` / `DropdownMenu` with one shared positioning hook; `⋯` opens right-aligned past the viewport midline.
- Browser surfaces (selection color, focus rings, scrollbars) themed from tokens. Icons: Phosphor only, no emoji.
- **Comments explain why, and they must stay true.** When a rule changes, the paragraph above it changes in the same edit.
