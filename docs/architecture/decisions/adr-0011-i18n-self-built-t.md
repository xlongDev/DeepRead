# ADR-0011: i18n——自建轻量 t(),zh 为源语言,不引库

日期:2026-10-28
状态:已接受(实施随 B9.1 批次)

## 背景

v0.3 要做界面多语言(B9.1)。现成方案是 react-i18next / formatjs 一类,但
本项目的文案面是「单一 UI、静态目录、无复数/性别等复杂规则」的中等规模中文
界面;引库换来的 ICU 能力大部分用不上,而库的体积、Provider 层级与测试耦合
却是全量成本(ADR-0001:<100 行的功能禁引依赖)。

## 考虑的选项

1. **react-i18next**:生态默认,但 Provider/插件体系与按需加载对单一静态
   目录是过度设计;测试需额外配置。
2. **自建 t() + JSON 目录**:一个 `t(key, vars?)` 纯函数 + 每语言一个 JSON,
   支持变量插值即可覆盖当前全部文案形态;约百行以内。
3. **不做 i18n**:zh-only 与「全平台」定位冲突,排除。

## 决策

选 2,落地为两段式:

1. **抽取段**:自建 `shared/src/i18n/`(轻量 t() + JSON 目录),**zh 为默认
   源语言** —— 组件里的硬编码中文机械迁出到 `zh.json`,key 缺失时回退显示
   key 本身(开发期可见)。抽取期冻结新增 UI 文案(与功能批次错峰)。
2. **翻译段**:en 目录 + 语言设置项。

测试环境语言锁定 zh:现有契约测试(Library 等 1,287 行断言中文文案)不做
任何改动 —— t() 在测试下恒返 zh。

## 后果

- 运行时零依赖,包体不受影响;en 目录缺失的 key 回退 zh,永不白屏。
- 代价是没有 ICU 复数/性别规则:当前文案不需要;真需要时在 t() 内加最小
  分支,仍优于为此引库。
- 新增 UI 文案的纪律:直接写中文进组件 = 抽取债。B9.1 完成后此纪律由
  review 把关(后续可考虑 lint 钩子,暂不做)。
