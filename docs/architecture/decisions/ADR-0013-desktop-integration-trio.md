# ADR-0013: 桌面三件套 —— 单实例、文件关联、托盘常驻

日期:2026-10-31
状态:已接受

## 背景

DeepRead 是本地优先的桌面阅读器,但桌面集成的三件基础能力一直缺席:

1. **双击书文件打不开**:文件管理器里双击 `.epub`/`.pdf` 不会路由到
   DeepRead,用户必须先开 app 再走导入对话框。文件关联是「本地优先」
   的自然延伸 —— 书在磁盘上,app 应该是它的默认打开方式。
2. **重复实例**:双击多本书会起多个进程,各自一份 SQLite 连接与
   同步定时器,轻则数据视图分裂,重则写库竞争。
3. **关窗即全退**:关掉窗口 = 进程退出 = 听书中断。TTS 播放引擎在窗口
   进程里,听书时「把窗口收起来、声音继续」是阅读器类产品的常见预期。

三者一起做:它们共享同一条「文件参数如何进入首实例」的通路,拆开做
会有两次协议改动。

## 考虑的选项

### 单实例

1. **tauri-plugin-single-instance**(官方):首个实例注册回调,后续启动
   只把 argv 转交给首实例后退出。零自研、覆盖三平台。
2. 自研(锁文件 + argv IPC):要自己处理陈旧锁、平台差异,无收益。

选 1。这是本 ADR 引入的**唯一新依赖**(官方插件,纯进程间消息转发)。

### 文件关联

1. **Tauri 内置 `bundle.fileAssociations` 配置**:macOS 生成 Info.plist
   `CFBundleDocumentTypes`,Windows 安装器写注册表,Linux 写 desktop
   文件 `MimeType`。声明即可,无运行时代码。
2. 自建深链协议(`deepread://open?path=…`):要引 deep-link 插件,且文件
   路径作为 URL 参数有编码/安全问题。

选 1。扩展名清单直接复用 `library::detect_format` 的白名单
(epub/mobi/azw3/fb2/cbz/pdf/txt/md),运行时二次校验,不信任扩展名。

### 托盘与关窗行为

1. **关窗 → 隐藏到托盘**,托盘菜单「显示 / 退出」,左键点图标 = 显示。
   听书跨窗口存活;⌘Q 与托盘「退出」仍是真退出。
2. 关窗 = 退出,托盘只是快捷启动器:听书被关窗打断,三件套的价值减半。

选 1。这是有取舍的产品决策:关窗后 app 仍在后台(同步定时器继续),
「退出」必须显式 —— 托盘菜单与 ⌘Q 都直达。托盘图标用 Tauri 2 内置
`tray-icon` feature,不引新依赖。

## 文件参数的进入通路(三件套的交点)

- **第二实例启动**(Windows/Linux 拖拽到图标):single-instance 回调拿
  argv → 过 `detect_format` → 发 `app.open_file` 事件给首实例 → 显示窗口。
- **macOS Finder 双击/拖到 Dock**:系统对运行中的实例发
  `RunEvent::OpenFile`(启动时携带文件也是同一路径),同样走该事件。
- **首实例冷启动带文件参数**(Windows/Linux):macOS 之外,启动 argv 的
  书文件也要打开 —— single-instance 插件只管「第二个实例」,首实例的
  argv 在 setup 里自行扫描,与上面两路汇聚到同一事件。

前端只认 `app.open_file`:导入(按 hash 幂等)→ 打开进阅读器。导入失败
(不支持/文件消失)如实走书架问题条。

## 后果

- 新依赖:`tauri-plugin-single-instance`(官方)。
- 关窗行为变化:用户「关掉」窗口后 app 仍在托盘;退出入口 = 托盘菜单
  或 ⌘Q。首次遇到需要在托盘找退出,是本决策接受的代价。
- dev 模式(tauri dev)收不到 OS 层文件关联事件 —— 该路径只能对打包
  产物验收;`app.open_file` 事件链路本身有测试覆盖。
- 托盘常驻意味着同步定时器在「关窗」后继续运行 —— 与「本地优先、
  后台静默同步」的产品语义一致。
