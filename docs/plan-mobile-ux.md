# 移动端 UX Epic:侦察报告与分批计划

> plan-v0.3 §9.6(XL,独立 epic)的承接文档。状态:**侦察完成,首批已落地**,
> 后续批次待真机验证后逐批排期。验证矩阵见 ADR-0007(Android 已出包、iOS 已验证)。

## 一、侦察结论(代码审计,2026-10-28)

### 已覆盖(无需实施)

| 能力             | 现状                                                                                                                                                                                                |
| ---------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **触摸滑动翻页** | 内核 paginator 原生支持:`touchstart/touchend` 同时挂在宿主元素与 section iframe 文档上(view 的事件隔离由内核自己处理)。分页/滚动两种形态都覆盖。**待真机验证**:滑动方向语义、与划词手势的冲突边界。 |
| 划词工具条落点   | `selection-place.ts` 纯算术定位,与输入设备无关。                                                                                                                                                    |
| 翻页芯片触摸可见 | 已修:`hover: none` 媒体查询下常显半透明(P0 批次)。                                                                                                                                                  |
| 进度/批注落库    | 全部走 IPC(桌面 SQLite / 浏览器 IndexedDB),与输入设备无关。                                                                                                                                         |
| TTS 三态/迷你条  | 应用内迷你条可用;**桌面悬浮条是第二个 WebviewWindow,Tauri Mobile 不支持** —— 移动端构建应隐藏该入口(见 W4)。                                                                                        |

### 差距清单(本 epic 的工作面)

1. **safe-area 安全区**:此前零处理 —— 刘海/Home 条会压住阅读器浮层与翻页热区。**首批已落地**:viewport meta 加 `viewport-fit=cover`,`.reader-top/.reader-bottom/.page-flip-*` 全部改 `max(原值, env(safe-area-inset-*))`(桌面 env 恒 0,零影响)。书架与弹窗类的 safe-area 待第二批。
2. **屏幕常亮**:阅读/听书时系统灭屏是最痛的移动失败。**首批已落地**:Wake Lock(特性探测,不支持的环境入口禁用),显示面板可关,页面隐藏自动释放、恢复可见重申(规范行为)。
3. **触摸目标尺寸**:顶栏 `chrome-button` ~26px、设置档位按钮,低于 44px 移动可点标准 —— 第二批审计+调整(桌面视觉不动,移动断点放大)。
4. **窄屏布局**:AI/学习/TTS 抽屉与设置面板的固定宽度在 390px 级屏幕的适配;双页版式在窄屏应不可选(现由 `scrollModeSupported` 类似口径,需真机确认内核 spread 行为)。
5. **键盘快捷键的移动等价物**:←→/空格翻页在触屏无意义;点击热区已覆盖,但「唤出 chrome」在触摸设备只有点按(无 hover)——已可用,待真机确认 2.5s 自动隐藏的节奏。
6. **桌面悬浮条入口的移动端禁用**(W4):`getCurrentWindow` 多窗口 API 在 Tauri Mobile 的可用性需验证。
7. **性能预算**:移动 WebView 的内存/主线程预算更紧 —— PDF 滚动虚拟化、字数统计分片(已落地)在这里收益最大;100MB+ 大书的移动端实测矩阵(performance.md 待办)应并入本 epic。
